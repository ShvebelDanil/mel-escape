# Шпаргалка: как добавить новую картинку в игру

Два сценария: **обычная именованная картинка** (монета, иконка, конкретный объект) и
**серия постеров** (poster1, poster2, … — подключается вообще без правки кода).

> ⚠️ **Всегда собирай с `-NoPngFallback`.** В игру идёт только `.webp`. PNG-фолбэки для фото
> весят в 10 раз больше вебпи (366 КБ против 36 КБ на постер) — это 90% веса релиза ради
> ~2% браузеров без WebP. Они у нас деградируют мягко и без них: бутылка рисуется
> canvas-заглушкой, постеры просто не появляются (остаётся пустая рамка), игра работает.

---

## Сценарий A: обычная картинка (с ключом в MANIFEST)

### 1. Положить исходник

```
assets/textures/_src/<имя>.png
```

Любой размер/формат (PNG/JPG/WEBP) — скрипт сам ужмёт.

### 2. Собрать игровую версию

```powershell
.\tools\build_textures.ps1 -Name <имя> -Max 256 -NoPngFallback
```

На выходе в `assets/textures/` появится `<имя>.webp`.

| Флаг | Когда нужен |
| ---- | ----------- |
| `-NoPngFallback` | **всегда** — иначе рядом ляжет PNG в 10 раз тяжелее (см. предупреждение выше) |
| `-Max 256` | макс. сторона в px — подбирай под то, насколько крупно объект виден в игре (иконки/монета — 128–256, постер на стене — 512) |
| `-Quality 90` | фото/градиенты, хочется меньше артефактов сжатия (дефолт 82) |
| `-Lossless` | плоская рисованная графика, логотипы, текст без полутонов |

### 3. Прописать в манифест

`source/textures.js` → добавить строку в `MANIFEST`:

```js
export const MANIFEST = {
  bottle: { file: 'bottle', mips: true, aniso: false },
  poster_x: { file: 'poster_x', mips: false, aniso: false }, // + новая строка
};
```

- `mips: false` — плоские UI/декоративные картинки, не уходят вдаль камеры (экономит VRAM)
- `aniso: false` — не видно под острым углом (спрайт-биллборд)
- `repeat: [x, y]` — только если текстура тайлится (пол, стены)

### 4. Использовать в коде

```js
import * as TEX from './textures.js';

// некритичное (появится не в первом кадре — постеры, декор):
const mat = new THREE.MeshBasicMaterial({ map: TEX.get('poster_x'), transparent: true });

// критичное (обязано быть готово к первому кадру):
await TEX.load('poster_x');
await TEX.preload(['a', 'b', 'c']); // несколько сразу

// DOM-иконка:
img.src = TEX.url('poster_x');
```

## Сценарий B: постер на стене (серия, без правки кода)

Постеры — особый случай: **в `MANIFEST` их дописывать не нужно**, они находятся сами при старте.

### 1. Положить и собрать

```
assets/textures/_src/poster1.png
```

```powershell
.\tools\build_textures.ps1 -Name poster1 -Max 512 -NoPngFallback
```

Дальше `poster2`, `poster3`, … — **по порядку, без пропусков в нумерации** (иначе поиск остановится на первом промахе).

### 2. Всё

Больше ничего делать не нужно. `TEX.discoverSeries('poster')` в `graphics.js` сама переберёт файлы при старте и подставит их в декор на стенах (`buildDecorUnit('poster')`) и в обстакл-стенды (`standBoard` в `entities.js`). Пока постеров нет вообще — рисуется только пустая рамка, ничего не падает.

### Сколько постеров нужно, чтобы не было одинаковых рядом

Картинки раздаются не случайно: каждый постер получает ту, **чья ближайшая копия дальше всего**
по коридору. Но в кадр помещается до **8** постеров сразу, поэтому:

| Картинок | Одинаковые в кадре |
| -------- | ------------------ |
| 5 (сейчас) | изредка, 2.7% кадров, копии не ближе 77 м |
| **8 и больше** | **никогда** |

Если хочешь железную гарантию — доведи серию до `poster8`. Код менять не нужно, всё подхватится само.

## Про папку `_src` — удалять нельзя, но и в релиз она не идёт

`_src/` — исходники в максимальном качестве. Рантайм их **не читает** (игра работает и без папки),
но удалять её не надо:

- это единственный способ **пересобрать** текстуру — поменять размер, поднять качество, вернуть
  PNG-фолбэк. Пересжимать уже сжатый `.webp` нельзя: каждое повторное сжатие добавляет артефакты
  поверх старых (как перефотографировать фотографию);
- в релизный архив `_src/` (как и `tools/`) просто **не кладётся** — на вес игры она не влияет.

Когда картинок станет много и папка начнёт мешать в репозитории — правильный путь не «удалить»,
а **вынести исходники наружу**: отдельная папка на диске/в облаке или отдельный art-репозиторий.
Хранить тяжёлые исходники в git плохо тем, что git держит все версии каждого бинарника навсегда,
и репозиторий пухнет необратимо.
