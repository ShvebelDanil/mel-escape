# Шпаргалка: как добавить новую картинку в игру

Два сценария: **обычная именованная картинка** (монета, иконка, конкретный объект) и
**серия картинок** (`poster1, poster2, …` для постеров, `board1, board2, …` для школьных досок,
`window1, window2, …` для вида за окном — подключается вообще без правки кода).

> ⚠️ **Всегда собирай с `-NoPngFallback`.** В игру идёт только `.webp`. PNG-фолбэки для фото
> весят в 10 раз больше вебпи (366 КБ против 36 КБ на постер) — это 90% веса релиза ради
> ~2% браузеров без WebP. Они у нас деградируют мягко и без них: бутылка рисуется
> canvas-заглушкой, картинки просто не появляются (остаётся пустая рамка/доска), игра работает.

## Сценарий A: обычная картинка (с ключом в MANIFEST)

### 1. Положить исходник

```
assets/textures/_src/<имя>.png
```

Любой размер/формат (PNG/JPG/WEBP) — скрипт сам ужмёт.

### 2. Собрать игровую версию

```powershell
.\tools\build_textures.ps1 -Name <имя> -Max 256 -NoPngFallback
```

На выходе в `assets/textures/` появится `<имя>.webp`.

| Флаг | Когда нужен |
| ---- | ----------- |
| `-NoPngFallback` | **всегда** — иначе рядом ляжет PNG в 10 раз тяжелее (см. предупреждение выше) |
| `-Max 256` | макс. сторона в px — подбирай под то, насколько крупно объект виден в игре (иконки/монета — 128–256, постер на стене — 512) |
| `-Quality 90` | фото/градиенты, хочется меньше артефактов сжатия (дефолт 82) |
| `-Lossless` | плоская рисованная графика, логотипы, текст без полутонов |

### 3. Прописать в манифест

`source/textures.js` → добавить строку в `MANIFEST`:

```js
export const MANIFEST = {
  bottle: { file: 'bottle', mips: true, aniso: false },
  poster_x: { file: 'poster_x', mips: false, aniso: false }, // + новая строка
};
```

- `mips: false` — плоские UI/декоративные картинки, не уходят вдаль камеры (экономит VRAM)
- `aniso: false` — не видно под острым углом (спрайт-биллборд)
- `repeat: [x, y]` — только если текстура тайлится (пол, стены)

### 4. Использовать в коде

```js
import * as TEX from './textures.js';

// некритичное (появится не в первом кадре — постеры, декор):
const mat = new THREE.MeshBasicMaterial({ map: TEX.get('poster_x'), transparent: true });

// критичное (обязано быть готово к первому кадру):
await TEX.load('poster_x');
await TEX.preload(['a', 'b', 'c']); // несколько сразу

// DOM-иконка:
img.src = TEX.url('poster_x');
```

## Сценарий B: серия картинок (постеры, доски, окна — без правки кода)

Серии — особый случай: **в `MANIFEST` их дописывать не нужно**, они находятся сами при старте.
Сейчас серий три, и они полностью независимы друг от друга:

| Серия | Куда попадает | Пропорции картинки |
| ----- | ------------- | ------------------ |
| `posterN` | постеры на стенах + обстакл-стенд | портрет, ~3:4 (собираем 384×512) |
| `boardN` | школьные доски на стенах + доска-подкат на колёсиках | **строго 2:1** (например 512×256) |
| `windowN` | вид за окном в коридоре | **строго 2.5:1** (например 640×256) |

Пропорции важны: картинка натягивается на полотно целиком, поэтому доска не 2:1 будет сплющена.

`windowN` — картинка **на всё окно целиком**, не на одну створку: перегородка (импост) нарисована
не в текстуре, а стоит отдельным бруском поверх стекла, поэтому вид за окном остаётся цельным.

### 1. Положить и собрать

```
assets/textures/_src/poster1.png
assets/textures/_src/board1.png
assets/textures/_src/window1.png
```

```powershell
.\tools\build_textures.ps1 -Name poster1 -Max 512 -NoPngFallback
.\tools\build_textures.ps1 -Name board1  -Max 512 -NoPngFallback
.\tools\build_textures.ps1 -Name window1 -Max 640 -NoPngFallback
```

Дальше `poster2`, `poster3`, …, `board2`, … и `window2`, … — **по порядку, без пропусков в
нумерации** (иначе поиск остановится на первом промахе). Нумерация у каждой серии своя.

### 2. Всё

Больше ничего делать не нужно. `TEX.discoverSeries()` в `graphics.js` сама переберёт файлы при
старте (по одному разу на каждое имя из `PIC_SERIES`) и подставит их:

- `poster` → декор на стенах `buildDecorUnit('poster')` и обстакл-стенд `standBoard` (`entities.js`);
- `board` → декор на стенах `buildDecorUnit('board')` и доска-подкат `board` (`entities.js`);
- `window` → стекло в декоре `buildDecorUnit('windows')`.

Пока файлов серии нет вообще — рисуется только пустая рамка (у досок — пустое зелёное полотно,
у окон — светлое пустое стекло), ничего не падает. Доска в интро-классе намеренно всегда пустая
и картинок не получает.

### Окна: основная картинка + пасхалка

У серии `windowN` раздача **другая**, и это сделано намеренно: все окна коридора должны выглядеть
одинаково, поэтому окно почти всегда показывает `window1`. С шансом **1%** вместо неё выпадает
случайная картинка из `window2`, `window3`, … — под пасхалки. Хочешь несколько разных пасхалок —
просто положи `window2`, `window3` и т.д., шанс на *любую* пасхалку останется 1%, они поделят его
между собой. Сам шанс — `PIC_RARE_CHANCE` в `source/graphics.js`.

### Сколько картинок нужно, чтобы не было одинаковых рядом

Картинки раздаются не случайно: каждый носитель получает ту, **чья ближайшая копия дальше всего**
по коридору, и у каждой серии свой независимый учёт. Но в кадр помещается до **8** постеров сразу,
поэтому:

| Картинок в серии | Одинаковые в кадре |
| ---------------- | ------------------ |
| 5 (столько сейчас постеров) | изредка, 2.7% кадров, копии не ближе 77 м |
| **8 и больше** | **никогда** |

Если хочешь железную гарантию — доведи серию до `poster8`. Код менять не нужно, всё подхватится
само. Для `boardN` порог ниже (досок в кадре меньше), но правило то же: больше файлов — реже повтор.

## Про папку `_src` — удалять нельзя, но и в релиз она не идёт

`_src/` — исходники в максимальном качестве. Рантайм их **не читает** (игра работает и без папки),
но удалять её не надо:

- это единственный способ **пересобрать** текстуру — поменять размер, поднять качество, вернуть
  PNG-фолбэк. Пересжимать уже сжатый `.webp` нельзя: каждое повторное сжатие добавляет артефакты
  поверх старых (как перефотографировать фотографию);
- в релизный архив `_src/` (как и `tools/`) просто **не кладётся** — на вес игры она не влияет.

Когда картинок станет много и папка начнёт мешать в репозитории — правильный путь не «удалить»,
а **вынести исходники наружу**: отдельная папка на диске/в облаке или отдельный art-репозиторий.
Хранить тяжёлые исходники в git плохо тем, что git держит все версии каждого бинарника навсегда,
и репозиторий пухнет необратимо.
